## Purpose

Partner discovery is the feature most members will use most often. It is what turns the platform from a database into a network — the moment when a Nairobi agritech startup finds the UK agricultural NGO that needs exactly what they're building, or when a Kenyan corporate finds an NGO partner with the community trust to make their CSR programme real.

The design principle: **warm, not cold.** Every connection is within a verified trust network, pre-filtered by shared values and active pledge commitments.

---

## How Discovery Works

### Search and filter
Members search the directory by:
- **Member type:** NGO / Charity / Corporate / Startup / Philanthropist
- **Chapter:** Kenya / UK / All
- **Thematic area:** Financial inclusion / Climate / Health / Education / etc.
- **What they're looking for:** Implementation partner / Technology partner / Funder / Expertise / Co-advocacy

### Profile view
Each member profile shows:
- Organisation overview (type, mission, size, geography)
- Thematic focus areas
- What they're currently offering (expertise, resources, platforms)
- What they're currently seeking (partnerships, funding, expertise)
- Documented Harmonia partnerships (with partner consent to display)
- Member since date and pledge status (green / amber only — red is not displayed publicly)

### Introduction request
Rather than cold messaging, members request a **warm introduction** via the platform:
1. Member selects a prospective partner and clicks "Request Introduction"
2. Chapter Coordinator (of either member) reviews the request and context
3. Coordinator makes a personal introduction via email, with both members cc'd
4. From there, it's a direct conversation between members

This gated model preserves the trust network quality — introductions are warm, not algorithmic.

---

## Cross-Chapter Discovery

Members can search across both chapters. Cross-chapter introduction requests are coordinated between the two Chapter Coordinators. This is how KPI 9 (cross-chapter partnerships) gets generated.

---

## MVP Implementation

For Phase 1 MVP:
- Airtable or Notion database with filterable member profiles
- Introduction requests via a simple form that notifies the Chapter Coordinator
- Coordinator handles all introductions manually

For Phase 2:
- Proper web interface with search, filter, and profile pages
- In-platform introduction request with automated Coordinator notification
- Partnership logging linked to discovery (close the loop on whether introductions became partnerships)
